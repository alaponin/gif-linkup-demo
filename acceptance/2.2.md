# Acceptance check — module 2.2 (MoEYS/PEMIS registered)

**Proves:** MoEYS is a member on the bus with subsystem PEMIS registered on its
Security Server and its service description published.
**Run by:** `scripts/acceptance.sh` (SS admin REST API)

- **Given** modules 2.1–2.2 are deployed;
- **When** the check queries the ss-moeys admin API (lite profile: ss-plr) for its
  clients and service descriptions;
- **Then**
  - client `PROGRESSA/GOV/MOEYS/PEMIS` exists with status `REGISTERED`;
  - service description `pemis-api` (OpenAPI3) exists and is **enabled**;
  - the parsed service URL targets `http://app-pemis:8000/v1`;
  - `app-pemis` answers a direct (non-X-Road) health probe with seeded data
    present (`curl http://localhost:… /v1/health` via docker exec).

Role note: PEMIS has no consumers in this slice by design. What 2.2 proves is
the 5.4 claim that the registration shape is identical for every member — and
MOEYS:PEMIS is the deliberate unauthorised caller in 2.6's negative check
("on the bus ≠ may call everything"). It also seeds the MOEYS/PEMIS join key
the KP3/KP4 packs build on.
