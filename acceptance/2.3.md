# Acceptance check — module 2.3 (PNEA registered as consumer)

**Proves:** the examination authority is admitted to the bus and its Security
Server can act as the consumer side of a cross-server call.
**Run by:** `scripts/acceptance.sh` (SS admin REST API)

- **Given** modules 2.1–2.3 are deployed;
- **When** the check queries the ss-pnea admin API for its clients, connection
  type and global-conf status;
- **Then**
  - client `PROGRESSA/GOV/PNEA/EXAMS` exists with status `REGISTERED`;
  - its connection type is `HTTP` (demo-only, per config);
  - ss-pnea holds current global configuration (it can see the other members in
    the registry — precondition for routing any call in 2.6);
  - the soft token is logged in and the sign + auth certificates are active.
