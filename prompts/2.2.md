# Generating prompt — module 2.2 (Register MoEYS/PEMIS on the bus)

**Building block(s):** member-moeys
**Produces:** `configs/member-moeys/2.2.yaml`
**Public spec:** NIIS X-Road member and subsystem registration; OpenAPI 3 service descriptions

## Problem

The Ministry of Education's school-information system (PEMIS) must become a member
on the bus: a registered identity (member + subsystem), a Security Server, and its
service description. This prompt generates that registration — the same shape every
member reuses (Module 5.4). Precondition: the member has passed the Member
Requirements checklist (Module 5.2; Interop Toolkit) — registration is the
technical step that follows readiness, not a substitute for it.

## Prompt (copy-paste ready)

```
Below is the NIIS X-Road member/subsystem registration reference and the Progressa
service brief for the Ministry of Education (MoEYS) with its school information
system PEMIS [paste both].

Generate the member-registration configuration as a single YAML document:
(1) member/subsystem identity is frozen in manifest.yaml's identity.members
    block (code, name, subsystem code, subsystem description) — an input to
    this prompt, not something it generates. Do not restate it;
(2) security_server — code and DNS name;
(3) services — the PEMIS API as an OpenAPI3 service description: service code and
    spec URL only. The forwarding URL, the enabled state and TLS-verify are not
    config fields — the Security Server reads the forwarding target from the
    spec's own servers.url, and always enables a service explicitly after
    publishing it, so a value here would just be a second copy to drift out of
    sync;
(4) access — the consumer subsystems permitted to call it (empty in this module:
    PEMIS has no consumers yet).

Rules: output every member code, subsystem code and service code as
[confirm: verify against the live X-Road registry] — do not invent identifiers; a
wrong code silently routes nowhere or to the wrong agency. Mark demo-only choices
(plain-HTTP service URL, TLS-verify off). Output only the YAML document.
```

## Inputs / outputs

- **Inputs:** the registration spec + the MoEYS/PEMIS service brief (+ the PEMIS
  OpenAPI spec).
- **Output:** `configs/member-moeys/2.2.yaml`, applied by `scripts/deploy.sh`.

## Safeguard

Validate every identifier against the registered subsystem list before deploy — a
wrong member ID silently breaks routing. Note: MOEYS:PEMIS is deliberately absent
from the 2.4/2.5 ACLs; do not "helpfully" grant it access — it is the negative
check in 2.6.
