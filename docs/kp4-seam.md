# The KP4 seam

KP2's slice is deliberately Joget-free: every member system is a mock behind
a stable OpenAPI contract. This page is the contract a KP4 author builds
against — what is frozen, the two shapes a Joget app can take, what the data
side promises, and what the host has to be able to carry.

## What is frozen

`manifest.yaml`'s `identifiers:` block — the instance, the member class, the
owner, the three canonical member subsystems and the two canonical service
ids — is the cross-pack contract. KP3 and KP4 build against those exact
strings. Amendment rule: only a **canonical** member may appear there, a
joined member never enters it (`hurl/check_scenarios.py` gates this), and a
change to the block is a cross-pack change requiring KP3/KP4 sign-off — not a
KP2 edit.

Everything else about a member is configuration.

## Shape A — replace a mock behind an existing contract

The three documents in `apps/specs/` are normative. A Joget app that serves
the same paths and the same 200-response schema is a drop-in; nothing in the
X-Road configuration changes, because X-Road was never told about the mock —
it was told about the spec.

The swap, in three lines: point the service's compose entry at the Joget
container instead of `apps/mock-registry` (the mock reads `CSV_FILE`,
`SPEC_FILE`, `ENTITY` and `KEY_FIELD`; a real backend reads none of them);
join the container to the `linkup` network so the Security Server can reach
it by service name; and set the spec's `servers.url` to the new backend's
address — that field, not any pack script, is the forwarding seam the
Security Server reads.

Two consequences worth knowing before you start. A backend served under its
own path prefix (Joget DX serves under `/jw/`, plus app and version segments)
produces a long consumer-side `r1` URL — expected, not a misconfiguration.
And `scripts/acceptance.sh` needs **no change at all**: assertion 5 (field
conformance, check 2.6.6) compares each response against its own OpenAPI
document, so it is the Joget-specific proof — it fails if the replacement
returns a field the contract withholds or omits one it requires, which is
exactly the failure mode a hand-built form introduces.

## Shape B — join as a new member

`apps/join-api/schema.py`'s `JoinPayload` is the whole submission format;
`POST /requests` with the applicant token, then operator approval. Four
constraints shape what a KP4 member may declare:

- **Identifiers** follow `docs/conventions.md` — the X-Road character set,
  and a `code` whose lowercase form is also a directory name and a manifest
  key (`[a-z0-9]+`, stricter than X-Road's own rule).
- **Read-only services.** `configs/x-road-bus/join-policy.yaml` sets
  `allowed_methods: [GET]`. A Joget app that *writes* over the bus is not a
  configuration change here — it is a policy decision about what the
  federation admits, and it has to be made before the payload is written.
- **Hosting defaults to `hosted_on`** an existing Security Server. That is
  the right default on a single-host demonstration: zero extra containers.
- **Own-server joins report `verified: false`,** and that flag never flips —
  the real answer is acceptance check 2.7.r1 against the running member, not
  the flag. `docs/production-delta.md` records why.

## The data contract

`apps/data/*.csv` — `persons.csv` and `enrolments.csv` generated by
`scripts/gen_seed_data.py`, `awards.csv` hand-written — is the fixture the
demonstration's assertions are written against, so a replacement backend must
serve the same rows for the same NINs or the acceptance suite is comparing
against data nobody holds. `scripts/seed.sh` regenerates those CSVs and
restarts every `app-*` container so they reload; it does **not** load data
into a replacement backend. Getting the fixture into a Joget app's own store
is that app's job.

## The capacity budget

Steady state today is ~11 GiB: four Security Servers, a Central Server, a
Test CA and the mocks. A KP4 demonstration adds the join API and one Joget
container on top of that. With a **hosted** join, that fits on a 16 GB host
with a few GiB of headroom — the pack's floor, not a comfortable margin. An
own-server join adds roughly another 2.2 GiB JVM and the CPU contention
`docs/production-delta.md` records; at that point the answer is a second host
or a larger one (`infra/DO-DEPLOYMENT.md` sizes both), never a trimmed
healthcheck.

## What this seam does not promise

It is a demonstration seam, not a production integration: everything in
`docs/production-delta.md` — the Test CA, the raw NIN on the wire, the
single-track federation, the silent drift of a third-party backend — is still
true on the other side of it.

There is deliberately **no acceptance check for this seam** in KP2. Assertion
5 already is the field-conformance test, and exercises 2–4 already run
join → drift → un-join; a dedicated seam check before any Joget app exists
would guard a failure nobody can yet produce. Write it as KP4's first commit,
against a real backend.
